The Poisson Match Model

How the engine turns two team names into expected goals, win/draw/loss probabilities, and a full distribution of scorelines.

← Overview Poisson model Elo ratings

The core idea

Goals in football arrive roughly at random throughout a match. If you know the rate at which a team tends to score against a given opponent, the number of goals it actually scores is well described by a Poisson distribution. The whole model is built to estimate one number per side — the expected goals, xG — and then let Poisson do the rest.

P(k goals) = e−λ · λk / k!
  where λ = the team's expected goals (xG) for this match

So the modelling problem reduces to: given team A versus team B, what are λA and λB?

Estimating expected goals

Each team gets two learned parameters:

ParameterMeaning
attackhow much this team inflates the goals it scores
defensehow much this team suppresses the goals it concedes

For a match at a neutral venue (the World Cup regime), expected goals combine the scorer's attack with the opponent's defense, on top of a shared baseline scoring rate:

xGA = exp( intercept + attackA + defenseB + elo termA )
xGB = exp( intercept + attackB + defenseA + elo termB )

The exp(·) guarantees a positive rate and makes the effects multiplicative: a strong attack and a weak opposing defense compound. When team A is the literal home side (not used for the neutral World Cup), a trained home_adv term is added to its exponent.

Why the exponential? This is a Poisson regression (a generalized linear model with a log link). The model learns the parameters on the log-scale, so the additive terms inside exp() become multiplicative scoring multipliers.

How the parameters are learned

The parameters are fit with scikit-learn's PoissonRegressor on every international result since 2010. Each historical match becomes two training rows — one for each team's goal tally — encoded into a sparse design matrix:

columns = [ attack0..n−1 | defense0..n−1 | home_adv | scorer_elo_z | conceder_elo_z ]
1
One-hot the teams. The scorer's attack column and the conceder's defense column are set to 1. So each row says “these goals came from this attack meeting that defense.”
2
Home advantage. A single shared column is 1 for the home team's row and 0 at neutral venues, so the model isolates the home boost from team strength.
3
Recency weighting. Older matches matter less. Each match gets an exponential weight with a 3-year half-life — a game from 3 years ago counts half as much as a game today (--half-life tunes this).
4
Elo features. Two extra columns carry each side's standardized Elo rating (scorer_elo_z, conceder_elo_z). This is the key cross-tier signal — see below.

Why the Elo features matter

Many national teams play almost exclusively against similar-strength regional rivals. Without a global anchor, a minnow that goes 2–2 with its weak neighbours would learn an “average” attack coefficient — collapsing the strength gap that should exist against an elite side it never faces.

The two standardized Elo columns inject a global strength axis that every match shares. They let the model express “scoring against a 1900-rated defense is hard” even for pairings absent from the data. This also gives a clean fallback: a team with no training rows contributes zero team-specific residual and is scored purely through its Elo (its attack/defense default to 0).

Coverage detail. Elo here is the project's self-computed history covering all 321 teams, not the bundled 48-team file — otherwise ~87% of historical matches (any game touching a non-qualifier) would be silently dropped.

From xG to match outcomes

Once xGA and xGB are known, the model produces outcomes in two complementary ways:

Analytical — exact probabilities

win_draw_loss_probs() assumes the two goal counts are independent Poisson variables and sums the joint PMF over every scoreline grid cell:

P(A wins) = Σa>b P(a|xGA)·P(b|xGB)
P(draw)  = Σa=b P(a|xGA)·P(b|xGB)
P(B wins) = Σa<b P(a|xGA)·P(b|xGB)

Simulated — sampling scorelines

For the tournament, the model draws goals directly: g ~ Poisson(xG) for each side. The CLI offers three sampling regimes built on this:

ModeHow it samples
randomfull Poisson draw — any scoreline can occur
plausiblenucleus sampling: keep the most probable scorelines until their cumulative mass ≥ confidence (default 0.80), then sample from that set — excludes freak results
modaldeterministic: take the single most probable outcome (with knockout draws broken toward the side more likely to advance)

Putting it together (predict-match)

Running wc2026 predict-match Brazil Argentina walks this exact path: resolve names → look up each team's attack/defense + Elo → compute xG → derive W/D/L analytically → Monte-Carlo 50,000 scorelines to rank the most likely results. With --ev it reweights scorelines by a prediction-game points scheme instead of raw probability.
