WC 2026 Winner Predictor

How the statistical model and simulation logic work — poc.py

The predictor answers one question: given every team's playing strength, how often does each team win the tournament? It does this in two layers:

  1. A scoring model that turns any pairing of two teams into an expected number of goals for each side.
  2. A Monte Carlo simulator that plays the whole tournament thousands of times using that model, then counts how often each team lifts the trophy.

This document covers only the modelling and match logic. Data loading, name normalization, and bracket plumbing are deliberately left out.

1. The scoring modelPoissonModel

Goals in football are well-described by a Poisson distribution: rare, independent events occurring at some average rate over 90 minutes. The whole model reduces to estimating that rate — the expected goals (xG) — for each side of a match. Once we have a rate λ, an actual scoreline is just a random draw from Poisson(λ).

The core equation

Each team gets two latent numbers learned from history: an attack strength and a defense strength. The expected goals for team A against team B combine A's attack with B's defense, plus a shared baseline and a home-advantage term:

λA = exp( intercept + attackA + defenseB + home_adv + elo_termA )

The exp(...) guarantees the rate is always positive, and it makes the effects multiplicative: a strong attack and a weak opposing defense compound rather than merely add. This is the standard log-linear form of a Poisson regression.

Fitting attack & defense (the design matrix)

Every historical match becomes two training rows — one per direction — so a single 2–1 result teaches the model both "A scored 2 against B's defense" and "B scored 1 against A's defense." The features are one-hot indicators selecting which team's attack and which team's defense are active: 

# Design matrix layout (one row = one team's scoring in one match):
#  [ attack_0 … attack_{n-1} | defense_0 … defense_{n-1} | home_adv | scorer_z | conceder_z ]

X[2*i,     hi]      = 1   # home team's attack is "on"
X[2*i, n + ai]      = 1   # away team's defense is "on"
X[2*i, 2*n]       = 1   # home advantage (0 if neutral venue)
y[2*i]               = home_score

PoissonRegressor then finds the attack/defense coefficients (plus intercept and home-advantage) that best explain all those goal counts. A small alpha=0.01 ridge penalty keeps the coefficients stable for teams with few matches.

Recency weighting

A result from 2011 should count for less than one from last month. Each match is weighted by an exponential decay based on its age, controlled by a half-life (default 3 years — a match that old counts half as much as a brand-new one):

weight = exp( −ln(2) · age_days / (half_life · 365.25) )

These weights are passed straight into the regression as sample_weight.

The ELO bridge (cross-tier calibration)

Pure attack/defense coefficients have a blind spot: a minnow that only ever plays other minnows looks "average" in its own little pool, because the model has no anchor tying the pools together. The World Cup mixes tiers that rarely meet, so this matters.

The fix is two extra global features built from each team's ELO rating, standardized to z-scores (scorer_z, conceder_z). They inject a universal strength scale that every match shares, so a team's coefficients are calibrated against the entire population, not just its usual opponents.

When ELO is active, the xG expression gains a symmetric strength term:

elo_termA = elo_atk · zA + elo_def · zB

Higher own-rating (zA) lifts A's expected goals; a stronger opponent (zB) is folded in via the defense coefficient.

Unknown teams & fallbacks

  • If a team appears in training, its fitted attack/defense are used directly.
  • If it doesn't but the ELO feature is active, its attack/defense default to 0 — the ELO z-score term alone then carries its strength.
  • If ELO is off entirely, an unknown team falls back to a rough estimate derived from how far its ELO sits from the mean.

From rates to a scoreline

xg(a, b) returns the two expected-goal rates; play(a, b) draws the actual integer scoreline from independent Poisson distributions: 

def play(self, a, b, rng):
    xa, xb = self.xg(a, b)
    return int(rng.poisson(xa)), int(rng.poisson(xb))

2. Match & knockout logic

Group matches

Every team in a group plays every other once. Each match is either a real result (if already played) or simulated via model.play. Standard points apply — 3 for a win, 1 each for a draw — and teams are ranked by (points, goal difference, goals for).

Knockout matches — extra time, no penalties

Knockouts can't end level. The model plays 90 minutes first; if the score is tied, it simulates 30 minutes of extra time. Because goals scale with time, extra time uses the same xG rates scaled down to 30/90 ≈ 0.33 of the regulation rate: 

def play_knockout(model, a, b, rng):
    ga, gb = model.play(a, b, rng)        # 90 minutes
    if ga == gb:                          # still level → extra time
        xa, xb = model.xg(a, b)
        ga += int(rng.poisson(xa * ET_GOALS_FRACTION))
        gb += int(rng.poisson(xb * ET_GOALS_FRACTION))
    return ga, gb

Penalties are deliberately excluded from the scoreline. If the match is still tied after extra time, the winner is decided by a 50/50 coin flip — the shootout advances a team but does not add goals. This matches the league's scoring rule, where knockout results are counted after 120 minutes excluding penalties.

3. Monte Carlo simulation

One simulated tournament is a single random outcome — useless on its own. The power comes from running it thousands of times (default 10,000) and treating the frequency of each champion as its win probability.

Groups→ R32→ R16→ QF→ SF→ Final→ 🏆 1 champion

Each full run threads one random-number generator through every match, so the whole tournament is internally consistent. The main loop simply tallies champions: 

wins = Counter(
    sim_tournament(groups, model, rng, actual, r32_override=r32)
    for _ in range(args.sims)
)
# win probability = wins[team] / total_sims

Already-played matches are pinned to their real results (the actual map), so the simulation only randomizes the future. A fixed --seed makes any run reproducible.
